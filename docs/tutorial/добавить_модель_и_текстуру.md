# Как добавить модель и текстуру блока

Модель связывает блок с его текстурами и говорит, как их выбирать.
Текстуры — это PNG-картинки 16×16 (как тайл).

---

## Папки

- Модели: `data/vanilla/model/block/{id}.json`
- Текстуры: `data/vanilla/texture/block/{name}.png`

---

## Текстуры

Просто положи PNG 16×16 в `texture/block/`. Имя файла определяет ключ.

Различают три варианта использования:

### 1. Статичная текстура (одна картинка)

`texture/block/my_block.png` + модель без `variants`:

`model/block/my_block.json`:
```json
{
  "textures": {
    "base": "my_block"
  }
}
```

### 2. Варианты (несколько «кадров» внешнего вида)

Свойство `variants: N` — модель берёт `{base}_0`, `{base}_1`, ..., `{base}_{N-1}`.

Например `iron_ore` с `variants: 3` и файлами `iron_ore_0.png`, `iron_ore_1.png`, `iron_ore_2.png`:

`model/block/iron_ore.json`:
```json
{
  "textures": {
    "base": "iron_ore",
    "variants": 3
  }
}
```

В мире блок будет случайно выбирать один из вариантов — земля выглядит живее.

Так же сделана трава (`grass_0` … `grass_5`, `variants: 6`).

### 3. Анимация

Свойство `animation` (кадры по имени `{base}_0`, `{base}_1`, ...):

```json
{
  "textures": { "base": "water", "variants": 2 },
  "animation": { "frames": 2, "speed": 10, "loop": true }
}
```

---

## Как модель находит текстуру

1. `textures.base` — базовое имя текстуры (без расширения).
2. Если `variants > 0` → ищет `{base}_0`, `{base}_1`, ...
3. Если `variants` нет → ищет ровно `{base}`.

---

## Связь блок ↔ модель

Модель подхватывается по имени файла: модель `model/block/iron_ore.json`
применяется к блоку `iron_ore`. Ничего регистрировать вручную не нужно
(`DataLoader.loadModels` при запуске).

---

## Текстура в инвентаре

Иконка предмета = `texture/item/{id}.png` (если есть), иначе `texture/block/{id}.png`.
Поэтому для большинства блоков отдельная текстура предмета не нужна.
